# MCP readiness must observe reconstructed terminal cells

The first 0.3.2 release candidate, `8cfad63`, failed macOS plugin conformance in
[run 36177182543](https://github.com/runyte/runyte/actions/runs/36177182543/job/108210514566)
on 2026-09-25. Publication and tagging were withheld. The version bump was
reverted before incorporating this correction and preparing another candidate.

The real-editor MCP test reached the persistent terminal rename, then timed out
waiting for `namedDetached`. Its bounded output included
`terminal 1 named Dtachd`: the rename had succeeded, but cells already containing
`e` did not need repainting. `NativeEditor.wait_output` removed control sequences
and whitespace from retained PTY bytes instead of reconstructing the screen.
Neither operation can recover omitted unchanged letters. Cleanup also reported
an unsuccessful persistent client exit after the assertion failure.

The fixture now uses the existing benchmark terminal decoder and reads the
current screen's cells after each complete synchronized-update frame. Retained
raw bytes remain bounded diagnostic evidence, alongside a bounded screen tail.
Split UTF-8, cursor movement and erased cells are interpreted as presentation
changes; an old marker retained only in byte history cannot satisfy readiness.
The Escape framing correction from `18c6bee` remains in place. No production
Rust behavior, bridge runtime dependency or acceptance deadline changes.

Unix conformance installs the pinned decoder dependencies from
`benchmarks/requirements.txt`. Native Windows fixtures do not use the decoder.
The bridge README documents the Unix test dependency separately from installing
the dependency-free bridge.

`test_rename_readiness_reconstructs_cells_omitted_by_incremental_redraw` in
`bridges/runyte-context/tests/test_runyte.py` paints a baseline of repeated `e`
cells, then paints only the changed letters of `Detached`. It fails against the
original readiness matcher and passes with cell reconstruction.
`test_readiness_requires_current_complete_screen_and_decodes_split_utf8` covers
incomplete synchronized frames, byte-split Unicode and a marker erased from the
current screen but retained in history. The existing paused-editor input test
and original live/detached MCP workflow both pass with the new reader.

Linux validation: the full bridge suite with real editor integration enabled
passes 45 tests, with seven Windows-only or separately launched native fixtures
skipped. Native macOS validation remains required in the new candidate's CI.
