# MCP command-input failure

Examined on 2026-09-25 against `dev` at `e790945`, using the Linux plugin
conformance log from [CI run 36151899224](https://github.com/runyte/runyte/actions/runs/36151899224/job/108126952832).
That commit changes documentation only. Node conformance and real-host plugin
registration passed; the subsequent real-editor MCP acceptance step failed.

## Diagnosis

`test_two_agent_clients_read_live_and_detached_workspaces_edit_unsaved_and_observe_revocation`
timed out at its first `standalone.terminal('Claude', 'CLAUDE_LIVE_MARKER')`.
The child editor remained alive. Its output showed command text in the document,
word completion and an Insert-mode newline action, rather than the expected
terminal child's marker.

`NativeEditor.command` in `bridges/runyte-context/tests/test_runyte.py` wrote a
bare Escape, slept 100 ms and then wrote `:` followed by the command. This
does not separate the keys if the reader is descheduled across both writes.
Crossterm 0.29's Unix parser treats the queued `ESC :` bytes as Alt-`:`.
The command prompt therefore never opens, and later command characters can
enter Insert mode and modify the document. Sleeping before Enter or increasing
the marker deadline does not repair that byte interpretation.

The regression test deliberately stops its own fixture editor with `SIGSTOP`,
waits for the stopped-child event, queues the complete command, and resumes
with `SIGCONT` in a `finally` block. Against the original helper this reproduces
the missing child marker and command text inserted into the document. This
establishes the failure mechanism without relying on probabilistic machine load;
the original runner's exact scheduling history is unavailable.

## Correction and validation

The helper sends a complete CSI-u Escape report (`ESC [ 27 u`) before `:`.
Crossterm parses that as a distinct Escape even when all input arrives together.
The existing terminal-input exit (`Ctrl-\`) still precedes Escape when needed.
The command is queued in order through the same physical PTY input, with no
sender-side command sleeps. Existing child-output, rename and workspace
readiness checks remain responsible for observing results within their original
deadlines. Production Rust, MCP behavior and CI timeout limits are unchanged.

`test_queued_command_keys_keep_escape_separate_from_colon` in
`bridges/runyte-context/tests/test_runyte.py` fails with the original helper and
passes with the correction. It verifies a queued command from the document,
another from terminal Insert mode, actual child output, rename acknowledgement,
and the original document's exact contents through the MCP bridge.

The complete bridge suite passes on Linux with real editor integration enabled:
43 passing tests and seven Windows-only or separately launched native fixtures
skipped. This includes the original failing scenario and concurrent append
acceptance. Run from `bridges/runyte-context`, with `RUNYTE_CONTEXT_TEST_BINARY`
set to the absolute path of the built editor:

```sh
python3 -m unittest discover -s tests -v
```

The suite ran outside the filesystem/network sandbox so its fixture-owned
local sockets and PTYs could operate. The new regression is Unix-only and is
selected by the existing real-editor CI step on Linux and macOS. Remote CI
and native macOS execution of this correction remain pending.
